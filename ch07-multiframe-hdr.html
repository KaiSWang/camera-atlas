Vol. 07 · Multi-frame & HDR

多幀融合、HDR 與夜景模式
為什麼 「一張」照片要拍十張

現代手機的「神奇畫質」不是單張的勝利,而是運算攝影(computational photography)的勝利: 按下快門時其實拍了 5~15 張,然後對齊、合成、降噪。這一章把 HDR、MFNR、夜景模式這三個 多幀技巧拆開講,順便講系統挑戰。

Section 01 · 為什麼要多幀

單張 sensor 的物理極限 無法越過

Sensor 在單次曝光有兩個根本限制: (1) 動態範圍受限於 well 容量與 noise floor, (2) SNR 受限於曝光時間與 pixel size。要超越這兩個限制,只能從時間裡偷——拍很多張,合成。

▸ 多幀融合的三條技術線

多幀融合分三條主線:HDR 解決動態範圍、MFNR 解決雜訊、Night Mode 是兩者極致版。它們在系統面共用對齊與合成 engine。

Section 02 · HDR Merge

不同曝光的圖 怎麼合成成一張

傳統 HDR(Exposure Bracketing)拍 3 張:EV-2(短曝、留亮部細節)、 EV0(正常)、EV+2(長曝、留暗部細節)。然後在 ISP 把三張合一張。 核心難點:動態物體的處理(ghosting)與banding 控制。

01

對齊(Alignment)

手機在拍 3 張之間可能會稍微晃動。所以合成前必須把三張對齊。 通常用金字塔 + block matching:把圖縮小成多層金字塔,從最小層開始找位移, 逐層 refine。這是個 mature 但運算量不小的步驟。

02

選擇權重(Merge weighting)

合成不是「平均」,而是「每個 pixel 從最適合那張取值」: (1) 亮部 → 短曝那張(沒過曝), (2) 暗部 → 長曝那張(SNR 較好), (3) 中間 → 加權平均。權重通常用 well-exposedness 函數 (Mertens et al. 2007 的經典方法),曝光適中的 pixel 權重最高。

03

Ghost removal

場景裡的人或車會動,三張間不同位置。如果直接合成,動的物體會變透明、變雙影。 Ghost removal 的做法:檢測「跨幀對齊後仍有大差異」的區域,標為 ghost region, 在這個區域只用一張的資料(通常選 EV0),不做合成。

04

Tone mapping 收尾

合成後的中間結果是 14 ~ 16 bit linear HDR raw,還沒辦法直接顯示。 接下來丟給後端的 LTM 壓成 10/8 bit。所以「HDR 照片」其實是 HDR merge + LTM 一條龍, 兩者缺一不可。

現代 HDR 的演變
  • Sensor HDR(Staggered / DCG) 把多曝光下放到 sensor,ISP 直接拿合成 raw
  • ZSL HDR 不需要按下快門才拍——sensor 一直在拍不同曝光,使用者按下就取最近的合成
  • HDR video(HDR10、HLG)用 staggered 即時輸出,encoder 直接吃 10-bit HDR raw
Section 03 · MFNR(Multi-Frame Noise Reduction)

同曝光多張 怎麼把雜訊洗掉

光線中等(室內、傍晚)時,單張 SNR 不夠,但又不需要 HDR 那種誇張動態範圍。 MFNR 是合適的解法:拍 6~10 張同曝光,對齊後平均。 SNR 提升 √N 倍——10 張就是 3.2× 改善,等效 ISO 從 1600 降到 500。

A

Anchor frame 選擇

選一張當「基準」,其他張對齊到它。通常選清晰度最高、雜訊最低的那張 (sensor sharpness statistic 最大、ISO 最低)。 如果連拍時主體在動,還會選「motion 最少」的當 anchor。

B

Pixel-wise alignment

HDR 是全局對齊(因為曝光差太多,patch matching 不可靠),MFNR 是同曝光, 可以做更精細的pixel-wise alignment。常用光流(optical flow)演算法, 算每個 pixel 從 anchor 到其他幀的位移向量。

C

合併(merge)

對齊後的每個 pixel,從 N 張中加權平均。權重由「對齊信心度」決定: 對齊得好的 pixel 拿大權重,對齊失敗的(可能是運動物體)幾乎不取。 Google 的 HDR+ 演算法就是 MFNR 的代表作。

MFNR 的優勢是「同曝光,所以沒有 HDR 的色彩跳變」。劣勢是動態範圍提升有限, 高對比場景仍需 HDR。所以實務上很多手機同時跑 MFNR + HDR—— 先 MFNR 把單張畫質提升,再用 multi-exposure HDR 處理動態範圍。

Section 04 · Night Mode

把「拍不到」變成「拍得到」運算攝影的極限

Night mode 是 MFNR 的極致版本:更長的單張曝光(0.5~2 秒)、更多張(10~30 張)、 總曝光時間達 5~30 秒。沒有任何 sensor 物理可以單張做到——這完全是運算攝影的舞台。

Scenario · iPhone Night Mode 按下快門後
1 → 偵測到光線極暗,自動進入 night mode,顯示倒數秒數(例如 3 秒)
2 → 同時偵測手抖程度——抖得多就用「多張短曝」,穩定就用「少張長曝」
3 → 按下快門,連續拍 8~15 張,每張 100~500ms
4 → 全程顯示「保持穩定」提示,gyro 監控位移
5 → 所有 raw 送 ISP + NPU,跑對齊 + AI NR + LTM,約耗時 2~5 秒
6 → 輸出比眼睛實際看到還亮的「夜景」——這就是運算攝影的魔法
Night mode 的工程難點
  • 長曝光的對齊更難——單張可能就糊了,對齊精度受限
  • 暗部 AI denoise 是必須的——傳統 NR 救不回極暗的雜訊
  • 場景檢測決定模式——AI 場景分類(夜景 / 星空 / 室內 / 月亮)觸發不同參數
  • 使用者體驗——倒數時間長,要在 UI 上明顯提示,否則使用者會以為當機
Section 05 · ZSL Ring Buffer

「快門延遲為零」背後的硬體設計

多幀技術都需要時間。但使用者期待「按下快門 = 立刻拍到」。 解法是 Zero Shutter Lag(ZSL):sensor 在使用者進入相機後就一直在拍, 把最近 N 張存在 ring buffer 裡。使用者按下時,把「過去」的幾張拿出來合成。

▸ ZSL ring buffer 的時間軸

ZSL ring buffer 持續儲存最近 N 張 raw。使用者按下快門時(F0),系統把 F-3 ~ F0 取出送 multi-frame engine。所以「快門 lag = 0」其實是因為「畫面早就拍好了」。

ZSL 的系統成本
  • DRAM 一直在燒——8 張 raw 12MP 大概 200MB,持續佔用
  • Sensor 不能停——進入相機後 sensor 持續輸出,功耗顯著
  • 不適合 always-on 場景——智慧眼鏡的「環境感知」不能這樣燒電,要靠 sensor 自帶低功耗 mode
Section 06 · 本章重點回顧

多幀融合 系統面試重點

面試常問題
1 → HDR 用不同曝光,MFNR 用同曝光——目的不同,合成邏輯也不同
2 → 對齊永遠是難點:HDR 用 patch matching,MFNR 用 optical flow
3 → Ghost removal:檢測 alignment 後仍大差異的區域,只取一張
4 → Night Mode 是 MFNR + AI NR + 場景偵測 + UI 倒數的合奏
5 → ZSL ring buffer 是「零快門延遲」的核心,但功耗代價可觀
