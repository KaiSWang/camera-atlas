Vol. 04 · ISP Frontend

前端校正
把 raw 變回 可信任的訊號

Sensor 給出來的 raw,並不是「光的真實樣貌」——它偏暗、有死點、邊緣會變暗、色彩偏移。 前端 ISP 的工作就是把這些系統性偏差校正掉,讓後面的演算法能在乾淨資料上工作。 這一章把每個步驟拆開講,順序非常重要。

Section 01 · 順序的邏輯

為什麼這幾個步驟 不能換順序

前端 ISP 的典型順序是:BLC → LSC → Defect correction → Demosaic → WB。 順序不是任意的——每一步都依賴前一步的「假設」。理解這個順序背後的物理意義, 你才不會在面試被問到「為什麼 demosaic 不能放在 LSC 之前?」時答不出來。

▸ Front-end ISP 處理鏈

典型的前端 ISP 處理鏈。實務上各廠順序略有差異(如 WB gain 可能放在 demosaic 前),但 BLC 永遠是第一步、demosaic 一定在 WB 之前(或同時)。

Section 02 · BLC(Black Level Correction)

第一步 把「黑」對齊到真正的零

Sensor 即使在完全沒有光的情況下,讀出來也不是 0,而是一個小於 100 的暗電流值 (例如 64 LSB)。原因是暗電流(dark current)、readout offset、 ADC 內部的 reference。BLC 的工作就是把這個 offset 減掉,讓「黑」真的是 0。

01

為什麼要做

後面所有運算(LSC 補光、demosaic 插值、WB gain)都假設「pixel 值與光強成線性比例」。 如果不減黑電平,做 WB gain 時就會把這個 offset 也放大——例如黑電平 64,gain 4×, 結果整張圖黑色變成 256,畫面整體發灰。

02

怎麼做

最簡單的版本:output = max(0, input - black_level)。 進階版本會分通道(R/Gr/Gb/B 各自有不同 offset)、分溫度(熱的時候暗電流變大)、 甚至分區域(sensor 中心 vs 邊緣)。Sensor 通常會在影像邊緣留一圈 「optical black」遮光區讓 ISP 即時量測 black level。

面試小陷阱
  • 為什麼分通道做?因為 R、Gr、Gb、B 的 photodiode 在矽基板上位置不同,洩漏電流略有差異
  • 為什麼有 Gr 和 Gb 兩個綠?它們在 Bayer 上的相鄰關係不同,實際 offset 會差一點點
  • 動態 BLC 怎麼來?就靠 sensor 邊緣的 optical black row/column,即時量測
Section 03 · LSC(Lens Shading Correction)

為什麼照片中間亮、邊緣暗、四角還偏色

理想鏡頭應該把光均勻分布到 sensor。實際鏡頭:中央通光面積大、邊緣有 cos⁴ 衰減 (光學定律,無法避免)、加上 CRA 不匹配造成的色偏。LSC 用一張 校正圖(shading map)反向補回去。

▸ Lens shading 的兩個成因

兩種 lens shading:整體亮度衰減(luma)與不同顏色不同衰減(color)。LSC 通常存兩張表,分別補正。

01

校正表怎麼來

產線上用積分球(integrating sphere)提供完全均勻的光,拍一張, 理論上應該全圖一樣亮。實際上拍出來就是中央亮邊緣暗——把這張當作「shading 樣板」, 倒推每個位置需要乘的補正 gain。一個 4000×3000 sensor 不會存全部 gain, 通常存 33×25 或 65×49 的稀疏 grid,中間用 bilinear interpolation。

02

為什麼要分色溫

鏡頭塗膜對不同波長的穿透率不同,所以不同色溫下 color shading 的形狀也不同。 高階 ISP 會存好幾張校正表(daylight、tungsten、fluorescent...), 根據當前 AWB 結果插值合成當下要用的那張。

03

邊緣放大雜訊的副作用

問題來了:LSC 在邊緣補了 2× gain,意思是邊緣的雜訊也被放大 2 倍。 所以暗角看起來補亮了,但雜訊變很明顯。後面的 NR 演算法要對「邊緣區域」用更強的去噪。 這就是 ISP 後端為什麼要拿 LSC map 當作雜訊強度的參考。

Section 04 · DPC(Defect Pixel Correction)

每片 sensor 都有壞點 幾顆是「正常」的

所有 sensor 都有「死點」——某些 pixel 永遠輸出最大值(hot)、最小值(stuck)、 或隨機跳動(random telegraph noise)。一片 12MP sensor 有幾十到幾百個 defect 是正常的, DPC 的工作就是偵測 + 修補。

A

Static DPC(靜態壞點表)

產線上每片 sensor 都會被測試,把位置固定的壞點記在一張表(defect map)裡, 存進 sensor 的 OTP(One-Time Programmable)記憶體。ISP 啟動時讀這張表,直接知道哪幾個 pixel 不能信。

B

Dynamic DPC(即時偵測)

有些壞點是用久了才壞的(熱劣化、宇宙射線)。所以 ISP 還會即時跑一個檢測: 把每個 pixel 跟鄰居比較,如果差距遠超過鄰居之間的差距,就判定為壞點,當場修正。 這個閾值不能太低(會把細節誤判)、也不能太高(放過壞點)。

C

修補方法

最簡單:用同色鄰居的中位數替換。例如 R 壞點,就抓附近 8 個 R pixel 取中位數。 進階版會考慮邊緣方向——如果鄰居顯示這裡有水平邊緣,就只用左右兩個鄰居,避免跨邊插值造成模糊。

Section 05 · Demosaic(去馬賽克)

從 Bayer 到全彩 三分之二的顏色靠猜

Bayer raw 每個 pixel 只有一個顏色。Demosaic 的工作是把缺的兩個顏色「插出來」。 聽起來簡單,但這是整條 ISP 裡最容易出 artifact 的環節——zipper、moiré、false color 都來自這裡。

▸ Bayer demosaic:從每像素 1 色到 3 色

Demosaic 把單通道 Bayer 還原成 3 通道 RGB。每個 pixel 缺的兩個顏色靠鄰居「猜」,如何猜得聰明,是各家 ISP 的核心競爭力之一。

01

Bilinear(最笨)

缺什麼,就拿鄰居的同色平均。實作便宜,但跨邊緣處嚴重模糊, 高頻區會看到「拉鏈圖案」(zipper artifact)。現代 ISP 早不用這個。

02

Edge-directed(主流)

插值前先判斷邊緣方向——這個 pixel 是水平條紋還是垂直條紋? 如果是水平,就只用左右鄰居插值(不要跨邊緣)。最有名的演算法是 Hamilton-Adams 和 Malvar(MS demosaic)。

03

AI demosaic(新潮流)

近 5 年的趨勢是用小型 CNN 直接學 raw → RGB 的對應。Google Pixel 的 Night Sight、Apple 的 Deep Fusion 都用 AI demosaic 配合 multi-frame。 問題是運算量大,不在 ISP 硬體區塊裡跑,而是讀回 DRAM 由 NPU 處理。

常見 demosaic artifact
  • Zipper——邊緣有規律的紅綠交錯,bilinear 的招牌 bug
  • False color(假色)——細條紋或格紋附近出現原圖沒有的顏色
  • Moiré——拍布料、紗窗、遠處欄杆容易出現的條紋干涉,本質是取樣定理問題
  • Maze——AI demosaic 訓練不足時會學出迷宮狀紋路
Section 06 · WB Gain

White Balance 的前端工作 「該乘的 gain 在 demosaic 之前就乘」

AWB 演算法本身放在 5 章講(那是回授迴路的範疇)。前端做的事是:拿到 AWB 算好的 R/Gr/Gb/B gain 之後,把它「乘」到 raw 上。乘的時機選在 demosaic 之前或之後,各家 ISP 都不一樣。

時機 優點 缺點
Demosaic 之前 每色獨立 gain,精確度高;對 demosaic 友善 可能放大某些 channel 的雜訊
Demosaic 之後 在 RGB 上操作,實作直觀 已經混色,gain 不純粹

實務上 Qualcomm Spectra ISP 與 MediaTek Imagiq ISP 都放在demosaic 之前, 因為精確度更重要。WB gain 同時也是 sensor 飽和點的隱藏限制—— gain 太大會把 highlight 推爆,所以 AE 與 AWB 在系統層級必須協調。

Section 07 · 本章重點回顧

前端校正 面試核心觀念

記住順序與原因
1 → BLC 永遠第一——所有後續運算都假設輸入是線性的
2 → LSC 在 demosaic 之前——對單色 Bayer 補正比對 RGB 補正準
3 → LSC 會放大邊緣雜訊,後端 NR 必須拿 LSC map 做雜訊強度估計
4 → Demosaic 是 artifact 大戶——zipper / false color / moiré 都源自這裡
5 → WB gain 在 demosaic 前後都有派系,主流選前面
